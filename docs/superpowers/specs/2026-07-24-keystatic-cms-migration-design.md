# Keystatic CMS Migration — Design

**Date:** 2026-07-24
**Status:** Approved design, ready for implementation planning
**Repo:** `holleyy/gaspery` (branch `main`)

## 1. Context & goal

Every page of the site should be editable in a GUI.

The current GUI (Astro Editor) only surfaces `writing`, because it discovers collections by matching a collection key to a same-named folder of markdown files. That excludes the `apps` roster (a `file()` loader over a single `apps.json`) and, until a folder rename, `appPages`. It can never edit About, Now, or the homepage, whose copy is hardcoded inside `.astro` files — no content CMS can, because those are code.

Keystatic is config-driven rather than discovery-driven, supports **singletons** (one-off pages) and **nested repeating fields**, so it can cover the whole site. This migration adopts Keystatic as the single editor and retires Astro Editor.

## 2. Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | **Scope: everything in one pass** | Avoids a half-migrated state where some content is in Keystatic and some isn't. |
| D2 | **Storage: GitHub mode (hosted admin)** | Admin lives at `/keystatic` in production; edit from anywhere including mobile; saves commit to the repo. |
| D3 | **Dual storage: `local` in dev, `github` in prod** | Development and verification don't block on GitHub App credentials; production still gets the GitHub-backed hosted admin. |
| D4 | **`apps.json` → one file per app** | A Keystatic collection maps one entry to one file. Trades a single tidy file for a GUI-editable, reorderable roster. |
| D5 | **Commits go straight to `main`** | Solo site; a save publishes. No PR gate. |
| D6 | **Content format: Markdoc (`.mdoc`)** | Verified constraint, not a preference: Keystatic content fields emit `.mdoc` or `.mdx` only — plain `.md` is not supported. |
| D7 | **Riso photo figures → a Markdoc content component** | Markdoc disallows raw HTML. A `RisoPhoto` block renders byte-identical markup and becomes a reusable, GUI-editable block. |

**Non-negotiable constraint:** the rendered site must be visually identical before and after. This is a plumbing migration, not a redesign.

## 3. Architecture

### 3.1 Packages

```
@keystatic/core  @keystatic/astro
@astrojs/react  react  react-dom
@astrojs/markdoc
@astrojs/cloudflare
```

### 3.2 `astro.config.mjs`

```js
integrations: [sitemap(), react(), markdoc(), keystatic()],
adapter: cloudflare(),
```

`output` stays at its default (`static`). Public pages remain **prerendered**; only Keystatic's injected routes (`/keystatic`, `/api/keystatic/*`) render on demand. Implementation must confirm in the build output that every public route is still prerendered and only the Keystatic routes are server-rendered.

### 3.3 Deployment

The site becomes a Cloudflare **Worker** that serves prerendered assets plus the two on-demand Keystatic routes. `wrangler.jsonc` changes from `assets.directory` to the adapter's entrypoint:

```jsonc
{
  "name": "gaspery",
  "main": "@astrojs/cloudflare/entrypoints/server",
  "compatibility_date": "2026-07-19",
  "compatibility_flags": ["nodejs_compat"]
}
```

The `ASSETS` binding is configured automatically by the adapter. Build command remains `astro build`.

### 3.4 Auth & environment variables

GitHub mode requires four variables, generated by Keystatic's GitHub App wizard:

- `KEYSTATIC_GITHUB_CLIENT_ID`
- `KEYSTATIC_GITHUB_CLIENT_SECRET`
- `KEYSTATIC_SECRET`
- `PUBLIC_KEYSTATIC_GITHUB_APP_SLUG`

Local: `.env` (must be gitignored). Production: `wrangler secret put <KEY>`. Anyone with **write access** to `holleyy/gaspery` can then log in at `/keystatic`.

### 3.5 `keystatic.config.ts` (project root)

```ts
storage: import.meta.env.DEV
  ? { kind: 'local' }
  : { kind: 'github', repo: { owner: 'holleyy', name: 'gaspery' } }
```

## 4. Content model

### 4.1 Collections

**`writing`** — `src/content/writing/*` → `<slug>.mdoc`, `format: { contentField: 'content' }`
`title` (slug field), `date`, `readingTime`, `dek`, `draft` (checkbox), `content` (markdoc, with the `RisoPhoto` component enabled).

**`appPages`** — `src/content/appPages/*` → `<slug>.mdoc`, `format: { contentField: 'content' }`
`title` (slug field), `template` (select: `quiet` | `editorial`), `spreads` (array of object `{ heading, body }`), `content` (markdoc).
This is the payoff for the earlier diagnostic: `spreads` becomes a real add/remove/reorder block editor instead of a raw-JSON textarea.

**`apps`** — `src/content/apps/*` → `<id>.yaml`, data-only
`name`, `dek`, `meta`, `status` (select: `live` | `dev` | `planning`), `url` (optional), `order` (number).

Filenames must remain `grod`, `pls-fix`, `afterframe`, `top-secret`. With a `glob()` loader the entry `id` comes from the filename, which is what `apps/[id].astro` already matches on (`a.id === page.id`). The `id` field is therefore **removed from the schema** — it becomes the filename.

### 4.2 Singletons

**`about`** — `src/content/about/index.mdoc`, `format: { contentField: 'content' }`
`title`, `dek`, `content` (markdoc). Exposed to Astro as a one-entry content collection so `render()` works on the body. Existing inline links render natively as Markdoc links.

**`now`** — `src/data/now/index.json`, `format: { data: 'json' }`
`updated` (date), `title`, `dek`, `entries` (array of object `{ heading, body }`) where `body` is **`fields.markdoc.inline()`** — preserves the `<em>` emphasis on media titles without changing the markup. Rendered through Markdoc's renderer inside the existing `.now-page__entry` wrappers.

**`home`** — `src/data/home/index.json`, `format: { data: 'json' }`
`hero` (object `{ eyebrow, title, intro }`), `nowSummary` (object `{ building, reading, watching, listening, linkLabel }`). Plain text; imported directly by `index.astro`.

### 4.3 The `RisoPhoto` content component

```ts
import { block } from '@keystatic/core/content-components'

RisoPhoto: block({
  label: 'Riso photo',
  schema: { src: fields.text(...), alt: fields.text(...) },
})
```

Stored as `{% RisoPhoto src="..." alt="..." %}`. A `markdoc.config.mjs` tag maps it to an Astro component emitting **exactly**:

```html
<figure class="riso-photo">
  <img src="..." alt="..." loading="lazy" />
</figure>
```

Image files stay where they are in `public/`; `src` remains a text path. No asset migration.

## 5. Migrations

1. **`.md` → `.mdoc`** — 6 writing posts, 3 app pages. Update `content.config.ts` glob patterns to `**/*.mdoc`. Frontmatter unchanged. Verified safe: content contains no `{%` delimiters and only light emphasis/headings/one blockquote.
2. **Photography post** — convert 11 `<figure class="riso-photo">` blocks in `so-well-planned-it-feels-unplanned` to `{% RisoPhoto %}` tags. Verify rendered HTML is identical to the current output.
3. **`apps.json` → per-app files** — split 4 records into `src/content/apps/<id>.yaml`; switch the loader from `file()` to `glob()`; drop `id` from the schema; delete `apps.json`.
4. **Page prose → singletons** — extract copy from `about.astro`, `now.astro`, and `index.astro` (hero + now-summary) into the singletons above; each page keeps all its structure and styling and reads its copy from data.

### 5.1 CSS scoping (required — regression risk)

Astro's scoped styles only apply to elements present in that component's own template. Once prose is rendered from Markdoc, scoped selectors targeting it **silently stop matching**, changing typography.

Every selector that targets moved prose must become `:global()`. Verified cases:

- `.about-page__prose p` → `.about-page__prose :global(p)` — the `a` / `a:hover` rules are already `:global`
- `.now-page__entry em` → `:global(em)` — the `h2` and `p` elements stay in the template, so their rules keep working

Verified as needing **no** change:

- `.riso-photo` — styled in `src/styles/global.css`, not scoped to any component
- `src/pages/writing/[...id].astro` — its `.prose` rules already use `:global()`, because post bodies were already rendered content

This must be verified visually, not just by build success.

## 8. Risks & mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| Scoped CSS stops applying to rendered prose | High | Explicit `:global()` step + visual diff (§5.1, §7.2) |
| Photo figures mangled in conversion | High | Byte-identical component output; HTML compared before/after |
| Static → Worker deploy change breaks production | Medium | Branch-only until verified; user approves cutover |
| Markdoc alters prose rendering subtly | Low | Content pre-verified clean; visual diff catches drift |
| Secrets committed | Low | `.env` / `.env.production` already gitignored; production values only via `wrangler secret put` |

## 9. Out of scope

- Any visual/design change.
- Rewriting post content.
- Deduplicating the homepage "now summary" against the Now page (they currently duplicate; noted as a future cleanup).
- Moving photo assets into Keystatic-managed image fields.
- A PR-based editing workflow (explicitly declined — D5).
